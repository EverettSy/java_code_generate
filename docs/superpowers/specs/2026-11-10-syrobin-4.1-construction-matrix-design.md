# Syrobin Java Code Generate 4.1 建设矩阵

- 日期：2026-11-10
- 投入：1 人（AI 辅助），6 周
- 方案：第 1 周先正式发布 4.0.0，第 2–6 周建设并发布 4.1.0

## 1. 背景与现状

| 项 | 现状 |
|---|---|
| 版本号 | `build.gradle.kts`、README、`plugin.xml` 更新说明为 3.0.0；`plugin.xml` 的 `<version>` 写死为 5.0.0（打包时被 3.0.0 覆盖）；代码注释与界面写 v4.0 GA |
| 已完成未发布 | v4.0 M1（统一响应包装、树形表、外键主子表、智能查询规则、HTTP Client、全语法合并）、M2（EasyExcel、Vue3、JUnit5）、M3（自然语言建表、表结构演进 Diff、Flyway、模板包、SPI），测试场景 13–15 已覆盖 |
| 规模 | 20 套 FreeMarker 模板、21 个 Action、MySQL / PostgreSQL / Oracle / DM8 |
| 测试 | 32 个（`CodeGenerateDialogTest` 11、`CodeGenerateFullChainTest` 15、`CodeGenerateDialogRegressionTest` 6） |
| 技术债 | `CodeGenerateDialog.java` 3147 行，UI、状态与生成逻辑耦合 |
| Boot 3 | 已有 `bootVersion` 配置，校验注解按 `javax` / `jakarta` 切换；缺自动识别与 Boot 3 默认值 |
| 团队契约 | `.syrobin-codegen.json` 共 17 个字段，可读写，不强制；`schemaVersion` 为 "5.0"，与插件版本无关 |
| 自然语言建表 | `NaturalLanguageDdlInferenceEngine.inferDdlFromNaturalLanguage` 规则推导，入口在离线 DDL 页 |

## 2. 建设矩阵

| 建设域 | M0 · 4.0.0 发版（第 1 周） | M1 · 主窗口拆分（第 2 周） | M2 · Boot 3 与契约（第 3–4 周） | M3 · AI 建表（第 5 周） | M4 · 4.1.0 发布（第 6 周） |
|---|---|---|---|---|---|
| D1 质量收口 | 统一版本号、补更新说明、Plugin Verifier | 按页签拆分主窗口，行为不变 | — | — | 候选版自测、文档 |
| D2 Spring Boot 3 | — | — | 自动识别 Boot 版本、Boot 3 默认值、全模板 jakarta 检查 | — | 真实 Boot 3 工程验收 |
| D3 团队契约 | 明确 `schemaVersion` 含义 | 契约读取迁入 `GenerationSession` | 锁定风格配置、临时覆盖、`contractVersion`、错误显式报出 | 提示词带入契约命名规范 | 文档 |
| D4 AI 建表 | — | — | — | OpenAI 兼容客户端、设置页、解析器校验与回退 | Ollama / 通义验收 |

- D1 拆分必须先于 D3 和 D4，因为两者都要改主窗口。
- D4 放最后：依赖外部服务、不确定性最高。延期时整块移到 4.2，不阻塞其余三条线发版。
- 第 6 周是缓冲周，不安排新功能。

## 4. 各建设域设计

### D1 质量收口

- 版本号单一来源：以 `build.gradle.kts` 的 `version` 为准，删除 `plugin.xml` 中写死的 `<version>5.0.0</version>`，由 `patchPluginXml` 注入；界面上的版本号改为运行时读取插件描述，替换主窗口、侧边栏、设置页三处写死的 "v4.0 GA"。
- `TeamContract.schemaVersion` 定义为契约文件的格式版本，与插件版本解耦；旧文件照常读取，不迁移。
- 主窗口拆分：
  - 面板：`TablePickerPanel`（选表）、`GenerationPlanPanel`（生成计划）、`QueryRulesPanel`、`DataSourcePanel`、`OfflineDdlPanel`。
  - 共享状态 `GenerationSession`：来源模式、表清单与勾选、字段缓存、连接是否已验证、当前预览表、已加载的团队契约；面板通过监听它的变化来刷新，不再互相修改字段。
  - `CodeGenerateDialog` 只负责组装面板、顶栏、页脚与 OK / Cancel。
  - 测试从反射读取主窗口私有字段，改为通过各面板的包级访问方法读取。
  - 按面板逐个拆，每拆完一个就提交一次。

### D2 Spring Boot 3

- 新增 `BootVersionDetector`，依次读取：
  1. `pom.xml` 的 `spring-boot-starter-parent` 版本或 `spring-boot` 依赖版本；
  2. `build.gradle(.kts)` 中 `org.springframework.boot` 插件版本；
  3. `gradle/libs.versions.toml`。
- `resolveBootVersion` 的优先级：调用参数 > 团队契约 > 自动识别 > 用户设置 > 默认 "2"。
- Boot 3 默认值：文档注解默认为 OpenAPI 3；Boot 3 下选 Swagger 2 时给出提示（springfox 不支持 Boot 3）。
- 界面：高级配置显示「Spring Boot 3（识别自 pom.xml）」，可手动修改。

### D3 团队契约强制

- 工程根目录存在 `.syrobin-codegen.json` 时，以下配置在主窗口只读，带锁形图标，提示「由团队契约锁定」：
  - 表前缀、基类、忽略列、Boot 版本、文档注解、对象转换策略、权限注解、统一响应包装类与成功方法、校验开关、多模块路由。
- 不锁定：作者、模块名、选表。
- 「本次覆盖团队契约」开关：打开后可临时修改锁定项；页脚显示「本次偏离团队契约 N 项」；覆盖内容不写回契约文件。
- 契约新增整数字段 `contractVersion`，由团队手动递增，写入生成文件头部注释；版本不变时头注释不变，不额外产生 Diff。
- 契约中出现未知字段或非法取值（如未知的 `docStyle`）时显式报错，不静默忽略。

### D4 AI 建表

- 设置页新增「AI 建表（实验）」：
  - 开关（默认关闭）、Base URL、模型名、API Key（存入 `PasswordSafe`）、超时（默认 30 秒）、「测试连接」按钮。
  - 预置模板：OpenAI、通义（DashScope 兼容模式）、DeepSeek、Ollama（`http://localhost:11434/v1`）。
- 客户端：`POST {baseUrl}/chat/completions`，非流式；在 `Task.Backgroundable` 中执行，可取消；HTTP 使用平台自带 `HttpRequests`，不新增依赖。
- 提示词：包含目标方言、契约中的命名规范（如表前缀），要求只输出一个 SQL 代码块。
- 校验与回退：输出交给 `DdlSqlParser` 解析；失败时附带错误信息重试一次；再失败回退到规则引擎，并提示「已回退到规则推导」。
- 隐私：只发送用户输入的业务描述，不发送表结构或数据；首次使用弹窗说明发送内容与目标地址。
- 日志与错误信息中不出现 API Key。

## 5. 测试策略

- 每个里程碑以现有 32 个测试全绿为底线。
- 新增：
  - `BootVersionDetector`：Maven、Gradle、版本目录三种工程样例。
  - Boot 3 渲染全部 20 套模板，断言不含 `javax.`；选 OpenAPI 3 时不含 `io.swagger.annotations`。
  - 契约锁定：锁定项不可编辑；覆盖后页脚计数正确；非法契约报错。
  - AI 客户端：本地假服务器模拟正常返回、非法 DDL、超时，断言回退到规则引擎。
- UI 改动沿用 `testRenderWideAndCompactLayouts` 渲染截图，拆分前后对比。

## 6. 发布

- 沿用现有流程：打标签 `v{version}` 触发 CI 依次执行 test、buildPlugin、verifyPlugin、publishPlugin。
- 4.0.0 与 4.1.0 各写一份中英文更新说明，同步 README 的版本与能力列表。

## 7. 风险

| 风险 | 应对 |
|---|---|
| 主窗口拆分超过 1 周 | 只拆不改行为；按面板逐个提交；第 2 周末未拆完的面板留到 4.2 |
| 大模型输出不稳定 | 解析器校验，失败重试一次再回退，坏 DDL 不进入生成流程 |
| 第三方服务不可用或网络受限 | 默认关闭；未配置 Key 时行为不变；Ollama 可完全离线 |
| 工作区被其它工具整体覆盖 | 每个里程碑结束即提交；`.backup-*` 加入 `.gitignore` |

## 8. 不在 4.1 范围（4.2 备选）

- 新生成目标：MyBatis-Flex、Spring Data JPA、React + Ant Design、Kotlin。
- 其余 AI 场景：字段注释与枚举补全、查询规则推导、单元测试增强。
- 模板包从 Git / URL 分享与更新。
- CI 过期检测（把生成引擎移出 IDE 运行）。
- 契约的服务端强制与审批。
